# Implementation history

Short, dated records of **completed or active development cycles**. These complement the [living implementation plan](../IMPLEMENTATION_PLAN.md), which owns the **current status, roadmap and next actions**.

## Convention

- Filename: `YYYY-MM-DD-short-description.md`, using the local development date. For multiple distinct cycles on one day add a short topic or `-02` suffix.
- Each log should record: **stage/branch/PR**, outcome and notable decisions, changed implementation pieces, validation evidence, known limitations, and next handoff.
- **Never rewrite historical logs** just to change present status. Amend factual errors only and label corrections. Update the living plan whenever milestones or next actions change.
- Avoid duplicating lengthy technical specs already in `docs/M*.md`; link to them.
